# Demo — Walkthrough Plan Only

This is a proposed recording script, not a completed demonstration or a report of an executed run. No video, account material, or dataset is included.

## Suggested narrative

1. Explain the business task: turn relevant tender notices into potential partners with traceable sources.
2. Show the local dashboard and environment health in an approved isolated setup.
3. Explain manual authentication. Do not record credential entry, verification challenges, login QR codes, or browser profile contents.
4. Show a bounded keyword collection only if the target site, account use, and disclosure of the displayed information are authorized.
5. Explain project-history skips, field provenance, and why an award candidate still needs review.
6. Show a sanitized workbook/result view with clearly labeled synthetic or cleared data.
7. Show previewed add/fill/skip actions against a disposable Feishu target, only with separate authorization for that API interaction.
8. Explain the write-confirmation boundary. Demonstrating a write requires a separate explicit authorization; the walkthrough need not perform one.
9. Close with deployment, recovery, validation limits, and the role of AI-assisted development.

## Release checklist for a future recording

- Confirm rights to disclose both the UI and the technical narrative.
- Use a separate demo profile and a cleared or synthetic dataset.
- Hide account, browser, filesystem, integration, and desktop identifiers.
- Label any mockup, synthetic data, edits, or redactions accurately.
- Review frames, audio, captions, thumbnails, and metadata before adding the final artifact.
- Update the README and audit only after owner approval.

No live workflow should be inferred from this script. The portfolio is useful as an architecture case study while visual evidence remains pending.
